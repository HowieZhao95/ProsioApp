## User workflow and persisted format

Menu: Screenshot → Area, Window, Current Display, Choose Display. Region selection opens per-display overlays, Return confirms, another drag reselects, Esc cancels. Region selections are limited to one display. Window and display choices use native controls with stable index identity; display labels include a number. Current display uses the pointer position captured when the action begins.

A screenshot is encoded to PNG before any result window appears. Each committed asset is one `UUID.prosiocapture` directory under `Application Support/Prosio/Captures`, containing `image.png` and a version-1 `asset.json` manifest. The directory itself commits atomically from a hidden pending directory, so there is no separate index write that can orphan successful PNGs. Directory manifests are reloaded at launch/reopen, newest first. Unknown versions and damaged/missing images are preserved and reported; incomplete hidden pending directories are ignored and preserved on reload. A save failure cleans only its own pending directory.

Metadata records stable UUID, version, capture time/kind/source, Quartz top-left global points source rect, and actual image pixel width/height. The image is a standalone PNG; no editor state is claimed at this milestone. Future document/annotation formats require their own versioned schema.

Results support PNG/TIFF pasteboard copy, PNG export with NSSavePanel overwrite confirmation, and Recent Screenshots reopen. The library offers Open, Copy, Save, and confirmed Delete. Closing either window leaves saved files intact. Raw app-specific errors remain visible through capture messages and a native failure alert.

Area shortcut: Ctrl-Shift-2 by default; configurable to Ctrl-Shift-3 or Off in the menu. Registration conflicts are reported; Carbon registration requires no microphone/Accessibility grant and does not claim to discover every third-party shortcut. Voice Escape and capture shortcut handlers route by signature plus ID. Capture rejects active voice phases; while capture is active the existing voice monitor is suspended without creating additional observation chains. Pending scheduled voice effects check suspension again. Cancellation and shutdown resume normal state without restarting a stopped monitor.

## M2 — unified native capture/edit session (2026-09-28)

The M1 notes above describe the retained baseline. M2 supersedes its region confirmation and result-window workflow. The approved direction is C, soft floating light/dark/system controls; the screenshot image itself is never recolored.

### Native workflow

`CaptureCoordinator` captures all target pixels excluding Prosio before constructing any overlay. A `CaptureEditingSession` then owns immutable `FrozenCaptureSource` images, selection, annotation history, drafts, output and cleanup. Releasing the region drag enters editing immediately. Eight enlarged-hit-area handles resize the crop and win hit-testing before any drawing tool; select-mode interior drag moves the crop. Annotation geometry remains in original image pixels when the crop moves/resizes. The first drag and subsequent moves/resizes use snapshot-bound snap candidates and 8/16-point acquisition/release hysteresis.

Window mode captures a desktop-independent window image once, then fits that entire frozen image inside a display, including cross-display or partially offscreen window targets. It does not change to visible desktop semantics during editing. Current/selected display modes start the same editor with the full source selected. Region mode opens per-display frozen canvases and remains limited to one display.

The toolbar provides select/move, rectangle, ellipse, arrow, text, pen, highlight, solid redaction, pixelation and blur, undo/redo, appearance, PNG/JPEG save, copy and exit. It measures the native host view content, applies compact layout where needed, and places it below/above/to the side or inside the crop while keeping it in view. No crop/resize button exists. Theme affects the controls and mask only. The removed `RegionSelectionSession` and `CaptureResultView` are not part of the application; history uses `openEditor` and the shared canvas/model/renderer.

Text uses a real NSTextView, the renderer's Helvetica typeface, shared pixel/display scale and zero text padding. New text layout is constrained to the selected area; existing text keeps its original layout width in a clipped container. Return and Cmd-C belong to the text editor. Cmd-Return commits the annotation. Marked IME input, including Escape, remains owned by NSTextView; without marked text Escape cancels the current text entry. Outside text entry Return/Cmd-C copies the screenshot. Empty edits delete the existing text annotation.

Only successful external copy/save completes the session and returns to the previously active non-Prosio application. Cancelling the save sheet or any output failure preserves the current editor state. Output locks all mutation. `CaptureOutputTransaction` retains newly committed history only after external output succeeds; failure rolls back only its own new asset, and reports any rollback failure. Screenshot acquisition failures have visible native alerts. Display topology changes force cancellation of the frozen session; shutdown and cancellation discard stale rendering/detection callbacks and restore the voice monitor without adding observation chains.

### Snap candidate capability limits

Window candidates use front-to-back window inventory, exclude Prosio, conservatively reject obscured rear frames, and require bounds/order stability across each capture. Local Vision detection runs in the background on the same frozen image and produces only high-confidence near-axis-aligned panel rectangles; cancellation, failure or stale results never prevent basic editing. There is no DOM access, network upload, OCR, recursive UI Map, scrolling or new mandatory Accessibility permission. Visual rectangles are not guaranteed webpage div identities; ambiguous content keeps free dragging.

### v2 storage and recovery

A v2 committed directory contains `source.png`, `document.json`, flattened `image.png` and `asset.json`. `EditableCaptureDocument.restrictedToSelection()` copies only current-selection source pixels, shifts related annotations into that image's pixel coordinates, and clears transient selection. Full-screen frozen images remain in memory only. Reload verifies source/flattened dimensions and document crop consistency. Existing v1 PNG assets remain readable and can be edited through the shared canvas.

Debounced automatic drafts use the separate hidden `.drafts` store. Only selected source pixels and editable state are written; previous draft generations are removed after a new generation succeeds. Drafts are not formal history. Explicit session cancellation deletes its current new draft. Crash-surviving drafts appear in Recent Screenshots under Recover unfinished screenshots; Resume opens the same editor, and successful output removes the resumed draft. Cancelling resumed editing preserves its original recoverable draft. No guarantee is made for a gesture or IME composition not yet committed to the editor snapshot.

### Screenshot translation — 2026-10-03

The floating toolbar now has a persistent translation button, including in narrow selections. Click translates into Simplified Chinese by default; its context menu selects Simplified/Traditional Chinese, English, Japanese, Korean, French or German and remembers that choice. While running, click the spinner or press Esc to cancel. Editing, crop changes, history navigation and session closure cancel old work and invalidate its result. Output waits until translation completes or is cancelled.

Vision recognizes only the selected visible image on a worker, with a maximum recognition edge of 4096 pixels. Export keeps the original pixels and dimensions. The translation pipeline deduplicates lines, batches up to 40/3500 UTF-16 units, permits two requests at once, and reuses session-local recognition, translation and layout caches. At most 200 regions/16000 UTF-16 units are accepted per selection. Excess content asks the user to select a smaller area.

Translations are normal editable text annotations with optional source/font metadata; old documents continue decoding. Local glyph comparison estimates common font families and weights, while source glyph metrics estimate size. Ink-bound CoreText layout preserves that size when possible, extends into free space inside the selection, wraps, then shrinks only if necessary. Nearby text and manual annotations constrain expansion. Only the original text rectangle is covered with sampled background; foreground sampling retains colored text. Re-translation replaces prior overlays in one undo step. Manual annotations, selected source pixels, draft recovery, PNG/JPEG exports, copying and pinning share the renderer. Redacted regions are skipped, including blur/mosaic intersections. Background matching is approximate on gradients/photos; uncommon fonts and missing script glyphs use an approximate or system fallback. This is rectangular replacement rather than image inpainting.

Verification: 135 capture tests / 19 suites passed, covering native canvas light/dark/narrow layouts, editing, output rollback, persistence, geometry, translation cache/deduplication/concurrency, cancellation/stale-result discard, actual Vision OCR, redaction exclusion and exact output dimensions. 27 backend-client tests and 48 server translation/compose tests passed; server typechecking passed. Synthetic OCR sample: a 1920×1080 source with an 800×260 selection, two visible lines, 0.59–1.03 seconds. Cached identical translation returned in 0.03–0.04 ms in the regression run. A real six-segment English→Chinese model request succeeded in 2.69 seconds, preserving the URL and time. These are sample measurements, not an all-input latency guarantee.

Final verification after wiring Vision request cancellation: the signed application build, strict deep code-signature verification, and all 9 translation/OCR tests passed. The full 135-test capture regression preceded this final cancellation-only adjustment; the 9 affected tests were rerun afterward.

### Source typography preservation — 2026-10-03

Typography matching runs on the existing OCR worker and is cached with recognition, with no extra model request. Each selection permits at most 96 template rasters of 128×32 pixels (four shortlisted fonts per line); subsequent lines use metric-based estimates. Latin sans/serif/monospace regular, bold and common italic faces and Chinese sans/serif regular/bold faces are candidates. Optional `fontName` and `translationSourceRect` metadata survive geometry changes, save/reopen and text edits. New translations use visible glyph bounds rather than a full font frame's vertical margins. Wrapping can use nearby free space, capped to roughly four lines and constrained by selection bounds and neighboring regions. An unrenderable translation reports insufficient space instead of silently disappearing.
