# Prosio Watch 首版功能需求

日期：2026-10-03。本文定义下一阶段的功能范围，尚未实施。

让用户抬腕看到桌面任务是否需要自己处理、还剩多少额度，并用点选或一句话让原任务继续。首版面向一个用户、一台已绑定电脑、多个现有任务；优先接入当前已支持的本机 Codex，额度按账号与来源分别显示。

## 主要页面

| 页面 | 内容与入口 |
|---|---|
| 总览 | 待处理数、执行中数、电脑连接状态；优先列出需要回答或介入的任务；一张用户指定的额度摘要卡；入口为任务列表和额度统计 |
| 任务详情 | 任务名、Agent 来源、当前状态、必要上下文、完整问题与选项、最近结果摘要；按当前能力提供回答、语音补充和中断 |
| 额度与统计 | 各来源的剩余额度、恢复时间、当前任务计数和数据更新时间；支持手动刷新 |

通知直达对应任务和问题。表盘入口支持“待处理数”或“指定来源剩余额度”两种展示，点击进入对应页面；受后台更新影响时显示缓存状态。

## 首版常用能力

| 能力 | 具体要求 |
|---|---|
| 查看任务 | 默认先看待处理，支持切换执行中和最近任务；区分执行、等待回答、等待审批、本轮结束、中断、异常和状态待确认 |
| 回答问题 | 单个问题点选即提交；多个问题逐项填写后整组发送一次。展示选项说明；关键信息不能为适应小屏而截掉，复杂问题转交大屏 |
| 语音回答 | 从当前问题进入录音，显示目标任务和识别文本，可编辑、重录或取消；确认后把选择与补充条件作为一条完整回答发送 |
| 补充要求 | 对正在执行的同一任务追加一句话。发送到该任务当时执行的轮次，核对实际回执；轮次变化明确提示，不另建任务 |
| 请求中断 | 任务详情的更多操作中提供中断，经一次确认发送；显示“请求已接受”与“本轮已中断”的区别，说明已发生的操作无法撤回 |
| 稍后处理 | 关闭当前卡片，事项保留待处理；不取消任务，不暂停其他工作，不自动视为同意 |
| 大屏接续 | 在手机或电脑继续处理，保留来源、任务和问题定位。手机提供轻量承接页，电脑进入 Prosio 对应详情；来源应用不能精确定位时明确提供查找信息 |
| 查看回执 | 显示发送中、电脑已收到、原任务已记录输入、需要澄清、未送达、待确认、已失效或已拒绝；输入被记录不等于项目完成 |

各入口按来源能力和当前状态显示。操作审批、发布、付款、删除和权限修改在来源应用处理；语音“继续”不能扩大任务授权。首版不提供新建复杂任务、完整聊天、文件浏览、暂停后恢复或远程桌面。

## 额度与统计

额度优先展示“还剩多少”和“何时恢复”，辅以已用进度；不可把不同账号、窗口、百分比、分钟和金额相加。

| 信息 | 首版展示规则 |
|---|---|
| Codex 账号额度 | 分别展示来源返回的各计费类别和窗口，例如短周期、周额度；显示剩余百分比、重置时间及倒计时。窗口名称和长度跟随来源，不写死为固定时长 |
| Prosio 云端语音额度 | 显示当前周期剩余分钟、已用与总量、周期结束时间；本地转写不计入云端额度。总量缺失时仅显示已用，不推断为无限额度 |
| 余额与其他用量 | 来源确实提供余额、积分、Token 或费用时展示原单位与统计周期；缺少可靠数据时不展示，不根据剩余比例估算可执行次数或金额 |
| 任务统计 | 当前执行中、等待回答、等待审批及需介入异常的任务数；待处理总数按任务去重，不直接相加分类数。按已同步且状态有效的范围统计，过期任务列为待确认，不宣称覆盖未接入的 Agent |
| 更新状态 | 每个来源独立标明账号简称、最近更新时间、可用／未接入／刷新失败／缓存；一个来源失败不清空其他来源 |

Codex 的剩余比例按 `100 − 已用比例` 计算并限制在 0–100%；数据缺失不能显示为 0%。重置倒计时归零后等待新数据，不自行恢复成 100%。额度属于账号，不是当前任务独享；一个窗口耗尽即可提示该来源可能受限，不因另一个窗口有余量而显示“一切可用”。字段依据 [OpenAI 官方额度文档](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

Prosio 剩余分钟按 `max(0, 总秒数 − 已用秒数) ÷ 60` 计算，向下取整到整分钟；为零显示“已用尽”，大于零但不足一分钟显示“少于 1 分钟”。周期与恢复时间以服务端为准，转换为用户当地时间，不硬编码套餐额度。

打开统计页时刷新，页面可见时最多每分钟自动刷新一次；后台随来源事件更新。超过五分钟未确认的额度显示缓存提示。额度刷新成功不能代替“电脑在线”；连接或额度读取失败都不触发额度耗尽提醒。

## 通知与设置

- 默认提醒新待回答问题、需要用户介入的异常和来源额度不足；普通工具调用与进度不提醒。等待审批可提醒并引导到来源应用。
- 额度提醒在剩余首次降至 20% 及耗尽时各提醒一次，同账号、同类别、同窗口去重；新窗口重新计数。阈值可在手机调整或关闭，缓存数据不触发。
- 同一问题更新原事项，多端处理后旧卡片不可继续提交。任务完成提醒默认关闭；用户可开启，文案用“本轮结束”，不推断整个项目完成。
- 手机或电脑完成登录、电脑绑定和撤销、通知开关、额度来源选择；手表可快捷关闭本应用提醒。遵循系统勿扰设置，默认通知只展示摘要，可由用户开启完整问题预览。

## 连接与一致性

首次绑定在手机或电脑完成，手表显示绑定电脑名称。必须区分“手机可连接”“电脑在线”“Agent 可控制”；电脑休眠、Prosio 退出或来源失联时只显示上次状态和时间，禁用控制。

回答绑定具体任务、问题及版本，中断绑定具体轮次；补充按前述同任务语义路由。录音开始时固定目标，切换页面不改目标；问题变化后保留可复制草稿，要求查看新问题。发送前重新校验，连点只产生一次操作。请求发出后断线只核实原请求，不能盲目重发；离线可保存未发送草稿，恢复后需用户重新发送，不自动排队执行。

首版建议由 iPhone 承接绑定、通知和大屏页面；离开电脑时还需要可达的桌面与服务端通路。WatchConnectivity 连接的是配对 iPhone 与 Watch，不能代替 Mac 的远程通信；Apple 也提供手表访问服务端的路径。具体路由在开发前确定，以真机验证后台可达性，不承诺持续连接或固定推送延迟。[Apple 数据通信说明](https://developer.apple.com/videos/play/wwdc2021/10003/)

只同步任务摘要、当前问题、额度和回执；不把 Agent 的 API 密钥或完整聊天发送到手表。每次控制都核对有效授权；解绑或撤销后服务端立即拒绝控制，终端收到变更或重新校验失败后清除该账号缓存。手表本机退出账号时立即清理，不能依赖离线缓存授权发送。

## 开发依赖与交付顺序

| 阶段 | 交付与依赖 |
|---|---|
| 第一批 | 总览、任务详情、连接状态、额度统计及表盘入口。复用桌面状态模型与 Prosio 用量接口；新增 Codex 额度适配、账号与设备绑定、手机承接页及远程同步通路 |
| 第二批 | 问题点选、手表语音草稿、补充、中断及真实回执。复用桌面命令校验和去重；新增手表录音与转写适配，不能直接假设 Mac 转写实现可在 Watch 上运行 |
| 第三批 | 决策与额度通知、后台同步、多端一致和断线恢复；真机验证后一起构成首版交付，不把前两批当作完整上线版本 |

今日结束轮次数、历史用量趋势、智能叠放卡片、多电脑与更多 Agent 来源作为后续扩展；结束轮次去重统计不等于完成任务数。套餐购买及额度重置操作留在手机或电脑。

当前依据：Prosio 的 [用量接口](../server/app/api/usage/route.ts) 提供周期和语音已用／总量，当前 [套餐权益](../server/lib/entitlements.ts) 仍是试用占位实现。仓库尚无 Watch 与 iPhone 目标；因此本文中的手表能力和通信通路均为新增需求。

## 首版验收

1. 总览可在一次打开中看到待处理、执行中和指定额度；表盘及通知能直达对应内容。
2. 点选直接提交；语音“选 A，面向初中生，先出草稿，不要发布”经预览确认后完整进入原问题，原任务继续；取消录音不发送。
3. 补充进入同一任务并核对实际轮次；中断以原轮次终止证据确认，不仅检查发送成功。
4. 连点、断线和多端抢答不重复提交；旧问题与已结束任务拒绝旧操作，恢复连接不自动发送草稿。
5. 额度来源、账号、窗口、单位和重置时间正确；缺失值、缓存、已耗尽和无总量各有对应展示，低额通知去重。
6. 电脑休眠、手机不可达、额度来源失联和解绑均明确展示；在真机上验证后台通知、前台刷新、语音识别、手机承接和撤销授权后的行为。
