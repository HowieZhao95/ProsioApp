# Prosio 创作者录屏实施方案

更新日期：2026 年 9 月 30 日。本文将已确认的创作者录制需求拆为可独立实施、测试和审查的模块。工程现状是截图与录音转写已有实现，视频录制尚未接入。本方案取代旧截图计划中 M3 的录屏范围；旧截图工作和验收记录继续有效。

## 一期范围

菜单栏并列提供语音输入、屏幕截图、录音转写、屏幕录制。屏幕录制从选择来源开始，经录制控制到素材查看与剪辑软件交接，形成可重开、可重试的闭环。

一次录制包含一个屏幕、窗口或单屏区域，零至两路摄像头，独立开关的麦克风与系统声音。摄像头支持 Mac 内置、系统识别的 USB 摄像头及兼容采集卡；其中一路可使用 iPhone 连续互通相机。手机占用摄像头名额，不增加独立手机协议或多手机功能。

每个视频来源与每个音频来源独立保存原片。剪辑交接目标包含 Final Cut Pro、DaVinci Resolve、Premiere 和剪映，保持录制时间偏移、暂停和断连后的间隙。原生多机位结构与已对齐的多轨时间线分别验收，不能以生成 XML 代替软件导入验证。

录制默认 30 fps、均衡画质；不在本期加入特效、美颜、字幕、自动缩放、云同步、直播、完整多轨编辑器或多个无线手机。预览服务于检查素材，非破坏性首尾裁剪和常规 MP4 输出沿用旧录屏闭环要求。

## 技术与模块边界

采用现有 App target 下独立 `Recording` 目录，避免使支持 iOS 的 ProsioKit 引入 macOS 捕获依赖。公共数据采用 Foundation 值类型；平台层拥有 ScreenCaptureKit 和 AVFoundation；UI 只依赖协调器，不直接访问编码器。

| 模块 | 目录及负责人 | 产出与完成条件 |
| --- | --- | --- |
| 数据与恢复 | `Recording/Domain`、`Recording/Storage`，Luna 6 | 版本化录制清单、来源配置、片段时间偏移、原子保存、损坏隔离、重启恢复；文件系统与边界测试通过 |
| 同步采集 | `Recording/Platform`，Sol 6.1 | 真实屏幕视频、独立两路摄像头、独立麦克风和系统音频；主机时钟同步、分段写入、暂停继续、来源恢复、磁盘保护；编码与生命周期测试通过 |
| 剪辑交接 | `Recording/Export`，Sol 6.1 | FCPXML、FCP7 XML、剪映适配、文件路径和偏移处理；实际素材测试及四软件导入矩阵，明确版本限制 |
| 录制体验 | `UI/Recording`，主代理整合 | 原生来源选择、音频开关、倒计时、紧凑控制、结束反馈、历史、预览、重试与交接；明暗主题和小尺寸检查 |
| 应用协调 | `Recording/Integration` 与既有接入点，主代理 | 同级入口、音频资源互斥、快捷键协调、摄像头权限声明、退出等待写盘；既有语音、截图、会议回归 |
| 验收与提交 | 测试与 `docs/evidence/recording`，主代理 | 审查代理实现、真实设备与剪辑软件验收、证据记录、分模块提交；未验证项保持待验收 |

依赖顺序：先固定数据契约；数据、采集与交接并行实施；采集和存储就绪后接入协调器与 UI；最后运行端到端验收。简单模块和明确的独立测试交 Luna 6，时钟、写盘、恢复、格式转换等工作交 Sol 6.1，主代理决定节奏并负责最终验收。

## 时间与媒体约定

所有来源以同一个主机单调时钟为基准，清单保存整数微秒。每个片段保存来源身份、相对会话的起点、媒体内起点、实际可播放时长、相对文件路径、尺寸和采样属性。禁止用文件创建时间、串行启动顺序或只记录墙钟时间对齐。

暂停时关闭当前片段，恢复时启动新片段并统一扣除暂停时长；单来源断连只影响该来源，其他来源继续。断连期间保留时间线空隙，重连后用同一设备身份尝试恢复，不偷偷替换另一摄像头。不可恢复的屏幕来源应明确提示，保留已完成片段。

屏幕、摄像头和音频分开编码，滚动完成短片段以限制异常退出损失。完成片段后先校验媒体，再更新原子清单；临时片段不冒充完整素材。重启保留可验证片段，损坏数据与未完成文件留作恢复诊断。视频文件写入失败、背压、磁盘低水位必须进入可见状态，不能默默丢帧仍显示正常。

初始工程目标为每 60 秒滚动保存，磁盘低于 2 GB 时安全结束，默认最多两路 1080p30 摄像头；屏幕按来源比例限制编码尺寸，性能能力通过实机测试确认。两小时录制的各来源同步偏差目标不超过一帧，音频与口型目标不超过 50 ms；这些是验收标准，未经实测不宣称已达到。

## 剪辑交接方案

优先复用四款剪辑软件已有的交换格式和成熟适配实现；第三方插件在确认名称、许可、接口及目标版本后接入。以录制清单为统一来源，分别生成适配文件。FCPXML 生成原生多机位角度，屏幕和两路摄像头分别成为角度，主麦克风和系统声音保持独立可控制。Resolve 和 Premiere 的 FCP7 XML 路线先保证独立多轨对齐，再验证原生多机位结构；不可把混合音频片段等同于多机位序列。导出后提供定向打开已安装剪辑软件的动作，打开请求和软件内导入成功分别记录。附带 Premiere 实验性多机位 XML 和 Resolve FCPXML 角度结构，默认仍使用对齐轨道路线。剪映自动交接需先通过具体 macOS 版本验收。

剪映使用经过版本验证的草稿适配；其格式不是官方稳定 XML 协议。现有开源实现作为参考候选，先检查许可、macOS 支持和实际导入；若当前版本不接受，保留原片与通用时间线，显示明确限制并继续完成适配，不假装已支持。

导出到用户选定文件夹，包含可移动的媒体与交接文件。重名、空格、中文、XML 特殊字符、文件缺失、断连间隙和长录制分段均需覆盖。首次导入可以由用户确认导入；“打开软件”与“软件已导入并对齐”分别验证。

可复用参考包括已固定 MIT 版本的 SnipSnipSnip 录屏生命周期、磁盘和恢复逻辑，以及 Apple 官方 ScreenCaptureKit / AVFoundation。多来源独立原片需要更细的编码与同步边界，不整体复制上游 AppModel 或泛用编辑器。移植代码保留来源和许可。

## 用户体验与应用协调

沿用当前已确认的柔和原生风格，紧凑菜单展示主要行动，独立设置窗口承载来源与预览。配置默认保留上次选择，设备消失时解释原因，允许去掉不可用机位后继续。权限按所选来源请求，无麦克风时仍能无声录屏，不以语音权限总开关阻挡录屏。

开始录制需要没有活动语音、会议录音或截图选区。活动录制独占本应用音频资源，禁用冲突语音触发并给出原因；结束和启动失败都恢复路由。录制过程的来源断连、磁盘告警、完成写盘与导出失败有明确状态和恢复动作。菜单和控制窗口默认排除在屏幕捕获之外。

停止和退出共用幂等收尾，等待文件完成后才允许正常退出。录制历史与语音、截图、会议数据分开存储，原片默认保留，不自动删除用户尚未交接的录制。

## 分步实施与验收

1. 建立模块契约和测试入口，写出独立模型与存储，再审查路径安全、版本兼容和异常退出恢复。
2. 完成采集平台与导出适配，使用合成画面和音频验证真实媒体编码、片段时长、对齐、暂停及错误路径。平台授权与设备发现保持按用户操作启动。
3. 集成来源设置、录制控制、历史预览、导出和应用路由。完成构建、现有测试回归与独立视觉检查。
4. 真实验收屏幕三种来源、四种音频组合、双摄像头、iPhone 连续互通、USB 拔插、长录制、磁盘不足、异常退出和权限撤销。
5. 将真实录制导入四款剪辑软件，检查素材原片、开始时间、断连空隙、音画同步、主音频选择、多机位切换与再次打开。
6. 按验收结果修复、分模块提交。构建通过、结构测试通过和实机通过分别记录，不以窄测试替代完整验收。
