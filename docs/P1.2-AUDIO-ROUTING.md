# P1.2 — Always-auto cloud routing, silence trimming, Opus upload

User decisions: no engine-mode setting (consumer app, fewer decisions) — routing is always automatic; trim silence on device; compress uploads with the best cost/performance codec.

## Measured (2026-09-26, gemini-3.5-transcribe SMART, 21.6 s zh/en sample)

| upload | size | audio tokens | text |
|---|---|---|---|
| WAV 16 kHz PCM16 | 694 KB | 540 | baseline |
| FLAC | 410 KB | 540 | identical |
| AAC 32 kbps ADTS | 91 KB | 543 | identical (±1 word) |
| **Ogg/Opus 16 kbps VoIP** | **43 KB** | 540 | identical |

Billing is by audio duration (25 tokens/s), not bytes → compression saves upload time/bandwidth, **silence trimming saves money**.

## 1. Upload format — Ogg/Opus (speech owns `ProsioAudio`)

- Encoder: Apple `AudioConverter` / `AVAudioConverter` to `kAudioFormatOpus`, 16 kHz mono, 20 ms frames, ~20 kbps (VoIP/speech tuning where available).
- Container: **Ogg** (RFC 7845: `OpusHead`, `OpusTags`, pages with granule positions + CRC-32) written by our own small muxer (`OggOpusWriter`). Ogg is Gemini-documented; CAF also worked but is undocumented → not used.
- Fallback: if encoding fails, upload WAV (as today). Server returns 415 for an unsupported format → client retries once as WAV.
- Debug recordings keep the original full WAV.

## 2. Silence trimming (speech)

`SilenceTrimmer` on the 16 kHz PCM before encoding — conservative; never lose speech:
- Energy VAD on 20 ms frames with an adaptive noise floor (e.g. 10th-percentile RMS of the session, floor −60 dBFS), speech threshold = floor + ~9 dB, with hangover.
- Remove leading/trailing silence beyond 250 ms padding; shorten internal silences longer than 700 ms to 300 ms. Never cut inside speech; keep ±150 ms around every speech run.
- Safety: if trimming would remove > 70 % of the audio, or the detected speech is < 300 ms, upload untrimmed.
- Report `originalSeconds`, `trimmedSeconds` in the debug recording.

## 3. Single-request cloud pass with routing + intent (server + core)

`POST /api/transcribe` (extends v0.2, backward compatible):
```json
{ "audio": "<base64>", "audioFormat": "ogg-opus" | "wav", "mode": "smart",
  "vocabulary": [...], "languageHints": [...], "sessionID": "uuid",
  "localTranscript": "…" | null, "hasSelection": false, "app": {…} | null }
```
Server flow:
1. If `localTranscript` present: one Jev evaluate call on it with both questions — the router `clean` boolean (router.ts) and the intent choice (§5b) — using the intent circuit breaker. Jev unavailable → treat as needs-cloud, intent `null`.
2. `clean ≥ CLEAN_THRESHOLD` **and** intent is `dictate` (or `edit`) → return the local text, **skip Gemini** (`source: "local"`). Usage metered by audio seconds as today (for quota) but no Gemini cost.
3. Otherwise Gemini as today (`source: "cloud"`). If the final's leading text differs from the local one (first ~6 non-punctuation chars) or the early intent was null, classify intent on the final (Jev, breaker applies).
4. Response: `{ "text", "language", "durationSeconds", "source": "local"|"cloud", "intent": { intent|null, confidence, source: "jev"|"unavailable", classifiedOn: "local"|"final" }, "route": { cleanProbability|null, reason } }`.
- `CLEAN_THRESHOLD` starts at 0.9 and is only lowered after `scripts/route-eval.ts` shows ~0 false-clean. While Jev is down everything goes to cloud (same as today, no added latency thanks to the breaker).
- Max audio raised from 120 s to 600 s (Opus keeps the body < 4.5 MB); WAV fallback keeps the 120 s cap.

Client (core):
- Remove `AppSettings.mode` / engine-mode choice; always this auto flow. Offline / backend unreachable → local transcript (as today's fallback).
- At stop: trim + encode, send one `/api/transcribe` with `localTranscript`; use the returned `intent` (null → IntentRules on the returned text). `/api/intent` stays for follow-ups/compat but the main path no longer calls it separately.
- Debug recording: `route.source`, `cleanProbability`, `originalSeconds`, `trimmedSeconds`, `uploadBytes`, `audioFormat`.
