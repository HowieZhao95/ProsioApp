# 创作者录屏开发验收记录

日期：2026 年 9 月 30 日。当前录屏实现已完成开发构建和自动化验收，完整产品目标仍在进行。真实长时间录制、两路物理机位以及四款编辑软件交接尚未验收，不能据本文将一期标记为完成。

## 已完成实现

屏幕、窗口及单屏区域视频采集，最多两路系统识别的摄像头，独立麦克风与系统声音，主机时钟对齐，暂停扣时，屏幕原目标重连、摄像头与麦克风同设备重连，最长 60 秒完成一个原片分段，2 GB 磁盘保护，写入背压反馈与等待收尾。

片段在验证可播放后写入恢复记录，原子保存恢复信息后发布原片和总清单。重启核对媒体，补回已完成但尚未登记的片段，恢复可播放的临时片段；损坏文件保留并给出警告。

原生录制来源设置、倒计时、浮动控制、菜单入口、历史、预览、首尾裁剪、可取消导出及失败重试均已有实现。停止后预览会重新加载实际有片段的机位，旧加载不能覆盖新机位。录屏与语音输入、截图、录音转写作为同级功能；本应用音频资源互斥，正常退出等待写盘。摄像头说明、连续互通设备发现标志和 hardened runtime 摄像头权限已在当前工程配置中接入。

FCPXML 生成视频多机位与独立音频；FCP7 XML 为 Resolve 和 Premiere 生成已对齐视频、音频与立体声通道；剪映为实验性明文草稿。预览和 MP4 保留来源空隙，原片不受裁剪影响，MP4 混合主麦克风和系统音频并平衡增益。

本轮补充了独立麦克风采集会话、设备启动/重连的完整收尾和会话代次隔离。麦克风断开不会要求停止屏幕或其他机位。交接完成后可由用户直接请求在 FCP、Resolve 或 Premiere 中打开；只记录打开请求，不能据此断言导入成功。剪映自动打开仍关闭，避免把未验证的 JSON 当作受支持导入。

优先复用现有交换格式、草稿适配及已确认接口的第三方插件。待用户提供具体插件名称后核对其接口与许可；支持软件名单不能替代角度、独立音轨及断连间隙的导入检查。

仅剩声音的恢复记录仍可交接四款软件，FCPXML 不再生成空多机位资源，界面保留查看原片与剪辑交接入口。

Premiere 包额外提供实验性多机位 XML，Resolve 包额外提供 FCPXML 角度结构。默认对齐轨道路线保持可用。XtoCC 厂商说明会折叠多机位，因此不能拿它证明原生机位保留；参考及格式证据见 [导出模块说明](../../../Apps/macOS/Prosio/Recording/Export/README.md)。

录屏独立复现：在 `tools/recording-validation` 使用 XcodeGen 生成工程，运行 `RecordingValidation` scheme 的测试。此目标是 hostless 测试，不启动 Prosio、不修改系统权限、不连接真实机位。界面测试仅创建测试进程的离屏窗口。

较早共享工作区回归为 209 项；最新隔离集成回归为 213 项，包含混合机位帧率、退出等待、屏幕恢复和仅音频交接。隔离副本与提交 `ff8b91d` 的 165 个主应用构建文件逐一相同，最新构建与严格签名验证通过。

两小时合成持续编码已完成：实际运行 7200.753 秒，三路 1920×1080@30 视频和两路 48kHz 双声道音频生成 600 个原片分段，写盘失败 0。只读媒体审计 600/600 元数据通过，时间线错误和片段间隙 0。编码跳帧 19 次、画面生成器跳过 25 帧、最大调度延迟 3.480 秒均保留为质量记录；采样 RSS 峰值约 231.3 MiB，末次约 56.3 MiB，媒体约 24.9 GB，队列峰值 16。完整报告与审计在 `synthetic-stress-2h/`。此结果只验证合成输入下持续编码和分段收尾，不证明真实设备两小时口型同步或全帧解码。
