# Prosio 截图与录屏集成计划

更新：2026-09-28。状态：M0 构建验证、M1 截图工程实现及自动化测试完成；真实截图交互尚待实机验收。D1“柔和悬浮”原型已确认并验证。原生 M2 已由 GPT-6 Sol 实施和独立测试，主代理审查、签名核验与模拟原生画布验收完成；88 项应用测试与 32 项语音/Core 回归通过。真实系统捕获、权限与多屏仍待实机验收；M3–M5 未完成。

## 1. 已确定决策

- 合进现有 Prosio，共用应用身份、菜单栏、设置和系统能力。
- 核心源码移植，再按实际依赖逐步拆模块。
- 首版优先打通核心工作流；滚动拼接等扩展功能暂不移植。
- UI/UX：极简、现代、克制、优雅；动效表达状态变化，不增加等待。
- 截图与编辑合为一次连续操作：框选后原地标注，直接复制/保存退出。用户明确以类似 Snipaste 的顺畅体验为方向；取消新截图主流程中的结果卡片和独立编辑窗口。
- 最新入口决策：不再区分区域、窗口、显示器菜单选项。菜单只保留直接的 Screenshot 按钮，与截图快捷键统一进入冻结快照上的框选；底层窗口/显示器捕获能力与历史数据兼容保留。
- 视觉已选 C“柔和悬浮”，支持明暗主题；不再等待三方向选择。取消独立裁剪/调整范围按钮，直接拖动八个边角手柄调整选区，提供吸附反馈，工具条始终在当前屏幕内可见。
- 第二期再做 AI 功能，一期只保存必要的数据边界与扩展接口。

本计划是新功能专项计划，不覆盖已有语音与商业化计划。下文为已确认的实施基线，三方向探索已完成。

## 2. 首版产品边界

目标：用户在 Prosio 内完成「唤起 → 框选并原地标注 → 复制/保存退出」，现有语音输入正常工作。最近素材重新打开是可选的后续入口，不是每次截图的必经步骤。

### 首版必须完成

| 模块 | 范围 | 核心验收 |
| --- | --- | --- |
| 入口 | 菜单栏截图、录屏、最近素材；独立快捷键，可改键并提示已知冲突 | 无需打开设置即可捕获；保留现有语音入口 |
| 截图 | 单一 Screenshot 入口直接框选；取消、重选；Retina 与多显示器坐标处理；底层窗口/显示器能力保留 | 图片与所选区域一致；不把自身选区遮罩和工具条拍进去 |
| 选区内编辑 | 松开鼠标后在原选区边缘显示工具条，直接标注、调范围、复制/保存 | 不出现结果卡片或二次“编辑”跳转；无标注时可直接复制；完成后返回原应用 |
| 标注 | 直接拖选区调整范围、矩形、椭圆、箭头、文字、自由画笔、高亮、模糊/马赛克/实色遮挡 | 编辑可撤销/重做；选中、移动、删除；预览和导出一致 |
| 图片输出 | 复制图片；PNG 默认，JPEG 可选；系统保存面板 | 外发图片固化标注和遮挡；不附带原始隐藏内容 |
| 录屏 | 区域、窗口、单个显示器；系统声音与麦克风分别开关；显示光标开关 | 无声、仅系统音、仅麦克风、两者混合均可完成录制 |
| 录屏控制 | 倒计时、录制时长、暂停、继续、停止、正在完成状态 | 连续暂停恢复不产生明显音画漂移；停止只执行一次 |
| 视频输出 | 预览、首尾裁剪、MP4 导出；默认 30 fps/均衡质量 | 原始视频保留；裁剪范围与输出一致；导出可取消、失败可重试 |
| 最近素材 | 图片/视频缩略图、类型过滤、重新打开、复制/导出、删除 | 与旧语音历史分别存储；重启可恢复素材列表 |
| 持久化 | 可编辑截图原稿、视频源文件及裁剪信息、版本化元数据、自动保存 | 不以扁平图片代替编辑原稿；可重新打开并继续编辑 |
| 可靠性 | 权限被拒/撤销、显示器断开、磁盘不足、异常退出后的可恢复内容 | 明确反馈和可行恢复入口；不承诺系统未写完的视频一定完整恢复 |

多显示器首版支持从多个显示器选择目标；不支持跨屏区域录屏与多屏合成录屏。区域截图跨屏边界首版可限制为单显示器并清楚提示，不能静默截错。

首版限制同一时间仅一个捕获流程/录屏会话。高级画质和帧率选项后续开放，不堆在首次使用路径上。

### 核心完成后再排期

延时/重复截图、置顶贴图、本地 OCR 与文字搜索、PDF/GIF/APNG、拖拽分享、高级图层、拼图、复杂展示样式、完整素材搜索/回收站。

这些功能从上一轮较宽的清单中移到后续，避免首版范围失控。最小存储清理能力保留：可见占用、手动清理、录制磁盘阈值；不默默清理正在编辑或尚未导出的素材。

### 本轮明确不移植

滚动拼接、连接 iPhone/iPad、UI Map、Guide 操作步骤录制、剪贴板监听、标尺/取色、对外 CLI/自动化、云同步、分享链接、AI 推理、字幕、自动缩放、摄像头叠加、多轨视频编辑。

不为未实现能力放置可点击但无作用的 AI 按钮。

## 4. 模块与集成边界

第一步采用同一 App target 内明确分目录的方式，减少大量 internal 类型跨包公开带来的移植成本。边界稳定后再提取 macOS 专用 Swift Package；不要让现有支持 iOS 的 ProsioKit 引入 AppKit/ScreenCaptureKit 依赖。

建议初始结构：

```text
Apps/macOS/Prosio/
  Capture/
    Domain/              素材、选区、状态、编辑命令等模型
    Platform/            系统捕获、录制、权限适配
    Screenshot/          截图流程
    Editing/             标注、渲染、图片输出
    Recording/           录屏、时间线裁剪、视频输出
    Storage/             原稿、元数据、缩略图、恢复
    Integration/         协调器与现有 Prosio 适配
  UI/Capture/            桌面快照、选区、原地标注工具条
  UI/Editor/             共享标注画布；历史素材重开可独立承载
  UI/Recording/          录屏设置、HUD、预览
  UI/Library/            最近素材
```

依赖方向：UI → 协调器 → 捕获/编辑/录制/存储；平台实现通过小接口注入。UI 不直接调用录制流、文件格式或未来的模型 API。

拆包目标先只考虑两个模块：不依赖 UI 的模型/服务契约，以及 macOS 捕获/媒体实现。是否进一步拆编辑和存储，依据真实依赖决定；不先制造六七个空模块。

### 边界吸附的数据来源

新增小型 `SnapCandidateProvider` 边界，提供候选几何、来源、置信度和快照版本。它只服务当前选区吸附，不引入完整 UI Map、OCR、滚动或网络服务。

- 窗口候选：复用现有 ScreenCaptureKit 窗口框；考虑前后顺序/遮挡，避免吸到用户看不见的后方窗口。
- 内容块候选：在冻结快照上本地检测清晰矩形/面板边界，绑定同一快照；模糊、无边框或重叠块没有可靠候选时保持自由拖动。图片不提供任意网页 DOM。
- 可选辅助功能增强：已有辅助功能授权时，仅取指针附近元素及少量祖先的几何；不读文字/URL、不遍历全树。浏览器暴露的结构不等于每个 div；失败或超时退回窗口/像素候选，不能阻塞基础截图。
- 所有候选在唤起时取得或绑定当时快照，不将后续窗口移动的位置混入旧画面。初版基于可用窗口边界起步，内容块效果必须实际验证后再宣称可用。

### 当前工程必须处理的接入点

- `AppEnvironment`：新增 CaptureCoordinator，负责装配，不继续把细节塞入组合根。
- `ProsioApp` / 菜单栏：统一入口；新截图在覆盖层内直接编辑，视频预览和历史素材重开可用独立原生窗口。
- `PermissionsManager`：增加屏幕捕获权限的按功能判断。旧 `allRequiredGranted` 仍供语音功能使用，不能成为截图总开关；无麦克风权限允许截图和无旁白录屏。
- `HotkeyMonitor`：现有语音键保留；捕获快捷键有自己的路由。已知冲突检测不声称能发现系统中所有第三方快捷键。
- `HistoryStore`：旧语音历史格式保留。新增 CaptureAssetStore 存大文件和索引，不把图片/视频塞入文本 JSON。
- 设置：新增紧凑的 Capture 分类，优先暴露快捷键、保存目录和音频默认项。语音和捕获的权限错误分别呈现。
- 原生 SwiftUI + AppKit；选区和浮层使用适合窗口层级与焦点管理的 AppKit，常规面板用 SwiftUI。

### 麦克风、快捷键和窗口冲突

首版建议录屏活动期间暂停 Prosio 语音触发，HUD/菜单给出简短原因，录屏结束后恢复。用户主动开始录屏时若语音会话仍在录音/处理，提示先结束该会话；不静默中断或丢弃文字。语音与旁白混用留给后续独立音频路由设计。

整个选区与原地编辑会话期间抑制冲突语音快捷键；Esc 优先取消正在绘制/输入的操作，再次按下退出会话。每次取消/完成都恢复事件监听、鼠标和原应用焦点。截图覆盖层、录制 HUD 默认从本应用捕获目标中排除并实机验证。

## 5. 数据与 AI 预留

一期只实现实际业务需要的契约，避免空置框架。

1. **CaptureAsset**：稳定 ID、类型、创建时间、源文件引用、像素尺寸/时长、可选来源应用、版本号。大文件独立存储。
2. **EditableDocument**：原图 + 可序列化标注/裁剪；视频源文件 + 非破坏性裁剪范围；编辑版本与素材关联。
3. **几何与时间约定**：明确屏幕点坐标、图片像素坐标、缩放比例、裁剪变换；视频派生数据关联源时间范围。避免未来 OCR 框和 AI 标注错位。
4. **DerivedArtifact**：允许后续关联 OCR、字幕、摘要和结构化建议。一期不运行这些 AI 任务。
5. **编辑命令入口**：UI 产生的修改走同一命令路径；未来 AI 先生成建议，用户应用后可撤销。
6. **处理快照入口**：可取得选区或固化标注后的图片、视频范围。未来默认上传这种明确范围的内容，不直接读取整个原稿包。

未来 AI 任务通过独立服务接入，持有素材 ID + 文档版本，支持进度、取消和过期结果处理。不要扩展当前仅面向文本的后端接口来暂存二进制截图；多模态后端契约在第二期单独设计。

内部原稿保留原始像素，第一期外发默认扁平图片/MP4。原稿分享和与上游 `.sss` 完整互操作不作首版承诺。项目格式要有明确版本与不兼容提示。

## 6. UI/UX 基线

### 信息架构

- 菜单栏：Screenshot 是单一直接动作，不展开区域/窗口/显示器子菜单；快捷键统一标为 Screenshot shortcut。录屏作为后续一级动作；最近素材为次级入口；原有语音功能继续可达。
- 唤起时：先取得不含自身浮层的桌面快照，再显示选区；选择与标注始终针对同一份画面，避免背景变化导致“选的是一张、导出另一张”。
- 框选时：选区主导画面，只显示尺寸和必要提示；松开后自动进入同位置可编辑态，不必再按一次确认或点击“编辑”。
- 原地标注：选区边缘一条紧凑工具栏，常用工具直接可达；颜色/粗细仅在使用相应工具时出现。工具栏靠屏幕边缘时自动换侧，避免被裁切或遮住选区。
- 调整范围：不设裁剪或调整范围按钮。八个边角手柄直接拖动缩放，边框有扩大命中区；无标注工具激活时内部拖动移动选区，工具激活时内部拖动绘制。手柄优先于绘制命中。更改范围不重新截图、不缩放已画标注；坐标仍锚定原始快照，导出按当前范围裁切。
- 吸附手感：用户已澄清“div”指窗口/网页内容块边界吸附。接近可识别边界时显示细对齐线并轻吸附；开始与脱离采用不同阈值，防止来回跳动。当前原型为进入 8 CSS px、脱离 16 CSS px；原生以屏幕逻辑点标定并实测调节。拖动本身直接跟手，不加阻尼动画。原型使用示例页已知窗口/内容块矩形验证手感；原生需分别验证窗口几何与网页块检测，不能假定截图含有 DOM，也不宣称可以识别每个 div。没有可靠候选时自由拖动，不胡乱吸附。
- 工具条避边：默认选区下方，空间不足依次尝试上方/两侧，最终限制到当前屏幕可用区域并留安全间距；极端满屏选区允许工具条浮在选区内，导出永不包含工具条。工具属性展开、主题切换、缩放和显示器变化后重新计算。移动换侧带滞回，避免贴边时反复跳位；窄屏时紧凑排列或折行，完成/保存/退出始终可达。
- 完成：复制按钮或 Cmd-C 直接复制并退出；未输入文字时 Return 同样完成复制。文字编辑时 Return 和 Cmd-C 交给文本控件（输入/复制文字），Cmd-Return 结束文字编辑，不能误把半句话复制退出。
- 保存：选择位置后成功保存才退出；取消保存面板或写盘失败返回同一选区，保留编辑状态。复制失败同样保留会话并明确反馈。
- 收尾：完成后恢复原应用焦点，显示短暂成功反馈，不弹预览窗口；取消未完成会话不加入最近素材。自动恢复草稿与正式历史记录分离。
- 历史素材：需要再次编辑时才打开独立承载窗口，复用同一标注模型/渲染器。

- 录屏：开始前选择范围/声音；进行中仅展示时长、暂停和停止；停止后先显示完成状态，再打开预览。
- 素材：独立轻量窗口，按时间展示；不在菜单栏展开复杂管理界面。

整屏冻结快照仅作为当前会话的内存底图；正式历史与恢复草稿持久化限定为用户选区及相关标注，不能因截一小块而长期保存整张桌面。新原稿版本保留 M1 v1 PNG 的读取能力。窗口截图需在开始标注前确定是独立窗口快照还是可见桌面像素，编辑过程中不切换底图语义。

### 视觉与动效

确定采用“柔和悬浮”：低饱和中性色、轻阴影、细描边、紧凑悬浮工具条，功能组之间使用细分隔线。优先系统字体和 SF Symbols；明亮/深色/跟随系统主题只改变 Prosio 工具、遮罩及选区控件，绝不反色或重染色冻结截图本身。深色工具条仍需与各种明暗底图有足够边界对比。

建议动效参数作为原型起点：反馈 100–160 ms，面板切换 160–220 ms；小幅淡入/位移，状态变化保持控件位置稳定。录屏中提供持续可见状态，不能只靠动画或颜色。尊重 Reduce Motion、Reduce Transparency 和键盘操作；首版无装饰性循环动效。

三方向探索已结束，A/B 留作设计追溯；C 按当前用户意见继续细化。HTML 仅作交互原型，生产应用保持原生。当前原型的主题与磁吸验证不等于原生功能已交付。

## 8. 验证与首版完成定义

自动化重点：坐标变换、编辑命令撤销、遮挡渲染、文档往返/版本处理、录制状态机、暂停时间映射、导出失败/取消、恢复与删除边界。

实机矩阵：

- 单屏 Retina、外接屏/不同缩放、窗口移动、断开显示器；验证区域边界与输出尺寸。
- 权限首次未授予、拒绝、撤销后重试；语音权限缺失不能阻塞截图。
- 四种音频组合，反复暂停/恢复，短片和至少 30 分钟录制；检查时长、音画同步、声音和磁盘占用。
- 捕获取消、关闭编辑器、关闭录制预览、应用退出；活跃录制退出时提供停止并保存/取消退出。
- 选区内会话：无标注直接复制；松开即标注；八手柄与内部绘制命中不冲突；吸附进入/脱离无抖动；调整范围后的标注定位；四边四角/满屏/极小选区及属性展开时工具条始终可见；明暗切换不改底图；文字输入时 Enter；取消保存后继续编辑；导出失败不退场；原应用后台变化不改变快照；完成后焦点恢复。
- 录制中断、磁盘阈值触发、写盘失败、导出取消；从实际可恢复的源文件继续操作。
- 存储测试采用模拟/隔离目录，不通过填满用户磁盘制造故障。
- 既有语音按住/切换录音、文本插入、历史与账户流程回归；不因新功能触发额外登录要求。

性能先在 M0 记录机器、系统、分辨率和基线，再设明确预算。重活离开主线程；长视频从文件读取，不整体载入内存；文件写入保持原子性、失败可恢复。正式性能指标不凭空承诺。

验收构建覆盖变动的 App 与媒体模块、现有相关语音测试。后端不改动时无需无关地重跑全部云端/计费测试。

首版完成意味着用户可在一个 Prosio 内完成两条真实闭环：框选并原地标注 → 复制/保存退出；录屏 → 裁剪 → MP4。最近素材可恢复，旧语音可继续用，权限/文件/录制异常有明确结果。
