# Prosio 便签 · 设计审核初稿

日期：2026-10-02。用户已确认 AppKit + WKWebView + Milkdown + 本地 Markdown 技术方案，本轮只设计体验、逻辑、UI，供用户审核，不实施生产功能。

## 共同理解与假设

便签是用户工作中的临时外部记忆：阅读、开会、写代码时随手记下信息，并能留在其它应用上方参考。核心不是管理大量笔记，而是减少「打开、定位、输入、保存」的中断。用户不需要进入主窗口，不希望出现登录、云同步、数据库或编辑/预览双栏；书写区就是排版结果，存储位置始终由自己选择。首先保证输入流畅、内容不丢、保存状态可信，再考虑视觉个性。当前以 macOS、单一活动便签、可打开已有文件为边界；多便签管理、图片附件、同步和 AI 整理暂不包含。此范围是待审核建议，不是用户已经认可的最终需求。

现有 Prosio 是原生菜单栏应用，已拥有全局快捷键和悬浮窗口能力。设计沿用系统字体、轻量中性面板、柔和边界、必要的蓝色操作强调。产品身份来源于本地源码与已有菜单原型；真实 UI 参考见 assets/existing-menu-light.png，原生 waveform 标志不需要在每张便签中重复。便签窗口的内容标题优先于品牌标题。不得捏造已发布品牌资产；没有外部产品摄影需求，任何图片都会分散编辑注意。

## 场景与流程

1. 菜单栏「便签」入口与可配置独立全局快捷键都唤出最后活动便签。默认快捷键候选 ⌃⌥N，必须注册并检测冲突，不能承诺必可用；首次启用无可用组合时菜单仍能打开。快捷键在隐藏时显示，已显示但未聚焦时聚焦，已经聚焦时隐藏。鼠标移开或点击其它应用不会隐藏。
2. 首次显示为空白未命名草稿，光标直接进入正文，轻占位「写点什么…」。没有教程弹层，没有强制保存步骤。保存区显示「未选择保存位置」和「选择位置…」。对草稿修改用应用内部恢复副本保护，这是崩溃恢复用途，不能标为「已保存到文件」。
3. 点击选择位置或 ⌘S，打开系统保存面板，用户选文件名和位置（默认建议从第一行生成可编辑文件名）。成功写入后，窗口标题显示文件名，底部显示「已保存」；后续同一文件自动保存。取消选择后仍保留草稿，不显示成功。
4. 常用入口永远靠近文字：标题、加粗、斜体、列表、任务项、引用、代码，完整功能进「格式」菜单。选中文本可提供紧凑浮动格式条。标准 Markdown 输入规则如 # 加空格转标题、- 加空格转列表；提供源码模式辅助检查，切换保持内容和撤销历史。
5. 默认开启置顶，保留钉住状态。正文不透明；失去焦点保持可读，不主动抢回焦点。窗口记住位置、大小、置顶状态；首次建议位于当前屏幕右上、与系统菜单栏和屏幕边缘各留 24pt。可移动，不固定在屏幕顶部。跨屏恢复需将窗口约束到当前可见区域。全屏应用与多桌面采用系统允许的浮窗行为，必须真机验证。
6. 「×」、⌘W 和聚焦便签时再次快捷键均为隐藏，不是删除；Esc 先关闭格式/更多菜单或弹层，没有弹层时隐藏；中文输入法候选框存在时 Esc 优先归输入法。再次调出恢复正文、光标和滚动位置。收起成条是可选设计方向，不能悄悄改变隐藏语义。
7. 更多菜单包含「新建便签」「打开 Markdown…」「另存为…」「源码模式」「在 Finder 中显示」「便签设置」。第一版只显示一个活动便签。切换文件前保存旧文件；未选择路径的非空草稿须给「选择位置并保存／保留草稿并继续／取消」，保留的草稿从菜单「恢复草稿…」可重新打开。第一版不做完整笔记库。

## 文件和状态模型

窗口可见性（隐藏、展开；可选收起）与文件状态独立；置顶是独立开关。文件状态：未选择位置、草稿已恢复、等待保存、保存中、已保存、保存失败、外部更改待处理。界面只展示用户需要知道的一项最重要状态；保存失败和冲突优先于普通状态。已保存必须意味着当前编辑版本写入成功，内部恢复副本不能代替这个承诺。

编辑停止约 1 秒后自动保存；中文组合输入结束后再序列化。选择路径后，每次写入携带文档ID和版本号，采用同目录临时文件与原子替换；串行写入，旧版本成功回调不得覆盖新版本的未保存状态。隐藏前、切换文档前、退出前触发最新版本保存；没有路径的文档只写内部恢复副本。磁盘或权限失败时留在可恢复状态，显示「未能保存 · 内容已保留」与「重试／另存为」。退出时若恢复副本也失败，必须提示保存或取消退出。

手选路径用系统保存面板；现项目未开启 App Sandbox，当前不强行引入安全作用域权限流程。将来启用沙盒时再使用安全作用域书签。记录上次文件路径和窗口偏好，应用本地恢复副本建议按文档ID保留最新快照、旧快照最多7天，正常退出后的未命名草稿保留到用户保存或明确丢弃。实际磁盘写入、文件监测都在原生层，HTML页面只编辑和发送内容。

打开的文件在外部变化：当前无未保存改动且未进行中文组合输入时可重新加载并保留合理光标；当前有改动则显示「文件在别处已修改」，提供「查看磁盘版本／另存当前内容／取消」，不得静默覆盖任何一方。外部删除或路径失效提示「原文件无法访问」，允许重试或另存为；用户取消后保留现有内容。

Markdown 基础子集为 CommonMark 加任务列表、删除线、表格。首版不提供图片上传、公式、附件或插件系统。对已有文件不能识别的语法或HTML，先保留源码，提示以源码模式打开，不能在无提示下经编辑器序列化删除内容；首次保存规范化 Markdown 前给必要说明。文本内容和语义保持，空白与标记风格可能规范化。

## UI 基础规范

三方向统一 1440×900 截图画布，展示真实可操作的桌面便签窗口（目标默认约420×480pt，最小320×240pt），外侧只有审核说明与演示控制，明确原型没有系统能力。每方向一个可离线双击打开的纯HTML文件，不引用CDN。模拟文件选择明确标注「保存位置演示」，不能假装浏览器已写入硬盘。演示内容统一并标明是假数据：标题「今天先记下」，正文「先把想法留下，再回到手头的事。」、二级标题「接下来」、任务项「整理会议中的三个要点」「把下一步发给同事」、引用「重要的不是记得更多，而是少打断一次。」，代码示例 `⌃⌥N`。不含私人信息。

正文至少16px、正文行距1.6–1.7，辅助标签≥12px，对比度≥4.5:1。控件焦点可见，主控件点击区≥28px，窗口支持缩放，浅色/深色均可读。第一版正文不提供透明度设置。成功状态克制、危险状态明确；未保存提示不能仅用颜色。窗口顶部承担移动/标题/置顶/隐藏，正文承担编辑，底部承担文件状态/路径/保存动作。格式工具不压缩主要书写空间，不重复品牌标志或制造仪表盘。

## 本轮交付与审核

交付：三个独立可操作方向HTML及截图、共同体验与状态逻辑设计、统一审核索引。可操作范围至少包括置顶切换、隐藏与恢复、保存位置演示/取消、编辑后状态变化、保存失败与重试、源码切换、主题切换。演示内容可编辑，但此原型不是Milkdown实现，编辑键盘规则不作为生产能力承诺。

视觉方向必须在内容区构图或工具分布上有结构差异，不能只换色。真实图片不属于该工具内容，因此不加装饰图。三方向是审核初稿，用户选择后才深化定稿；不要创建 direction-approved.md 或修改生产文件。
